 CONCEPT 1 — LINE PLOT AND BAR CHART (plt.plot, plt.bar)
══════════════════════════════════════════════════════════════

 Line plots show trends over time.
 Bar charts compare values across categories.

 plt.plot(x, y)             line plot
 plt.bar(x, height)         vertical bar chart
 plt.barh(y, width)         horizontal bar chart

 Common style parameters:
   color="steelblue"        fill or line color
   linewidth=2              line thickness (plot only)
   edgecolor="black"        bar outline color
   alpha=0.8                transparency (0 = invisible, 1 = solid)
   label="Series A"         used by plt.legend()
   marker="o"               dot marker on line plots
   linestyle="--"           dashed line

 CONCEPT 3 — FORMATTING: SUBPLOTS, TITLES, LABELS, GRID
══════════════════════════════════════════════════════════════

 Formatting makes charts readable and presentation-ready.

 Key formatting calls:
   plt.figure(figsize=(w, h))          set canvas size in inches
   plt.title("text", fontsize=14)      chart title
   plt.xlabel("text")                  x-axis label
   plt.ylabel("text")                  y-axis label
   plt.legend(loc="upper left")        show legend
   plt.xticks(rotation=45)             rotate x-axis tick labels
   plt.grid(True, axis="y", alpha=0.3) gridlines
   plt.tight_layout()                  auto-adjust spacing
   plt.savefig("file.png", dpi=150)    save to file

 Subplots — multiple charts in one figure:
   fig, axes = plt.subplots(rows, cols, figsize=(w, h))
   axes[row, col].plot(...)             each ax has the same methods
   axes[row, col].set_title(...)        prefix "set_" for ax-level calls
   fig.suptitle("Dashboard Title")      title for the whole figure

 CONCEPT 3 — sns.heatmap FOR CORRELATION, set_theme()
══════════════════════════════════════════════════════════════

 A correlation matrix shows pairwise linear correlations.
 Values range from -1 (perfect negative) to +1 (perfect positive).
 Near 0 means little linear relationship.

 df.corr()   computes Pearson correlation between all numeric columns

 sns.heatmap(corr, annot=True, cmap="coolwarm", vmin=-1, vmax=1)
   annot=True    show the value inside each cell
   cmap          color map: "coolwarm" (red=positive, blue=negative)
   fmt=".2f"     format cell numbers to 2 decimal places
   square=True   make cells square
   linewidths    spacing between cells

 sns.set_theme() controls the global look of all seaborn plots:
   style=   "whitegrid", "darkgrid", "white", "dark", "ticks"
   palette= "deep", "muted", "pastel", "bright", "colorblind"
   context= "paper", "notebook", "talk", "poster"

 CONCEPT 3 — OUTLIER DETECTION WITH THE IQR METHOD
══════════════════════════════════════════════════════════════

 The IQR method detects outliers without assuming a specific distribution.

 Steps:
   1. Q1 = 25th percentile
   2. Q3 = 75th percentile
   3. IQR = Q3 - Q1
   4. Lower fence = Q1 - 1.5 * IQR
   5. Upper fence = Q3 + 1.5 * IQR
   6. Values outside the fences are flagged as outliers

 Why IQR instead of std-based methods?
   - Robust to extreme values (std is inflated by the very outliers you seek)
   - Does not assume normality
   - Same logic used by matplotlib and seaborn boxplots

EXAMPLE ──────────────────────────────────────────────────────

def detect_outliers_iqr(series, multiplier=1.5):
    """Return (is_outlier_mask, lower_fence, upper_fence)."""
    q1  = series.quantile(0.25)
    q3  = series.quantile(0.75)
    iqr = q3 - q1
    lower = q1 - multiplier * iqr
    upper = q3 + multiplier * iqr
    is_outlier = (series < lower) | (series > upper)
    return is_outlier, lower, upper

col_data = df[target_col].dropna()

print(f"\n=== OUTLIER DETECTION ({target_col}) ===")
print(f"IQR fences: lower={lower:.2f}, upper={upper:.2f}")
print(f"Outliers:   {is_outlier.sum()} ({is_outlier.mean()*100:.1f}%)")

 CONCEPT 4 — A/B TEST DESIGN
══════════════════════════════════════════════════════════════

 A/B testing measures whether a change (treatment) performs better than
 the current state (control) with statistical confidence.

 Key terms:
   H0 (null hypothesis)   no real difference -- any observed gap is random
   H1 (alt hypothesis)    the treatment has a different conversion rate
   p-value                probability of seeing this result if H0 is true
                          < 0.05: reject H0 -> result is statistically significant
   z-statistic            how many std deviations the gap is from zero

 Z-test for two proportions (scipy):
   from scipy.stats import proportions_ztest
   count  = [conv_control, conv_treat]      # successes
   nobs   = [n_control, n_treat]            # total observations
   z_stat, p_value = proportions_ztest(count, nobs)

 Decision rule:
   if p_value < 0.05:  ship the treatment
   else:               do not ship -- insufficient evidence

EXAMPLE ──────────────────────────────────────────────────────
from scipy.stats import proportions_ztest

ctrl_visitors  = 4800
ctrl_conv      = 192
treat_visitors = 4900
treat_conv     = 245

ctrl_rate  = ctrl_conv  / ctrl_visitors
treat_rate = treat_conv / treat_visitors

z_stat, p_value = proportions_ztest(
    count=[ctrl_conv, treat_conv],
    nobs=[ctrl_visitors, treat_visitors]
)

print(f"Control rate:   {ctrl_rate*100:.2f}%  |  Treatment rate: {treat_rate*100:.2f}%")
print(f"z-stat: {z_stat:.2f}  |  p-value: {p_value:.4f}")
decision = "Significant -- ship the treatment" if p_value < 0.05 else "Not significant -- do not ship"
print(f"Decision: {decision}")

 CONCEPT 5 — SAMPLE SIZE AND TEST VALIDITY
══════════════════════════════════════════════════════════════

 An A/B test is only valid when the correct sample size is reached before
 reading results. Stopping early causes false positives.

 Key terms:
   alpha (alpha)   false positive rate -- typically 0.05
   power (1-beta)  probability of detecting a real effect -- typically 0.80
   effect size     the minimum lift you care about (e.g. 4% -> 5%)

 Sample size calculation (statsmodels):
   from statsmodels.stats.proportion import proportion_effectsize
   from statsmodels.stats.power import NormalIndPower

   es    = proportion_effectsize(p1, p2)         # effect size
   power = NormalIndPower()
   n     = power.solve_power(effect_size=es, alpha=0.05, power=0.80, alternative="two-sided")
   # n is required per variant (not total)

 Three classic test design flaws to recognise:
   1. Early stopping       checking results before required sample size is reached
   2. Multiple testing     running many metrics until one crosses p < 0.05
   3. Selection bias       rolling out only to best-performing user segment

EXAMPLE ──────────────────────────────────────────────────────
from statsmodels.stats.proportion import proportion_effectsize
from statsmodels.stats.power import NormalIndPower

baseline  = 0.04
target    = 0.05

es     = proportion_effectsize(baseline, target)
solver = NormalIndPower()
n_per_variant = solver.solve_power(
    effect_size=es, alpha=0.05, power=0.80, alternative="two-sided"
)

print(f"Baseline: {baseline*100:.0f}%  ->  Target: {target*100:.0f}%")
print(f"Required sample size: {int(n_per_variant):,} per variant before reading results")

flaws = [
    "Early stopping    -- checked p-value after 200 users instead of waiting for full sample",
    "Multiple testing  -- ran 20 metrics and reported the one that hit p < 0.05",
    "Selection bias    -- test rolled out to top-spending users only, not all users",
]
print("\nKnown test design flaws:")
for f in flaws:
    print(f"  {f}")

 CONCEPT 7 — SECURITY GATE: PII MASKING IN OUTPUT  (CIA: C)
 ─────────────────────────────────────────────────────────────
 Confidentiality means: personal identifiers must never appear in reports,
 charts, or any output that leaves the trusted processing boundary.

 Two protection layers:

 1. mask_pii_columns(df, pii_patterns)
    Detect columns whose names match PII keywords (email, phone, ssn...).
    Replace every value in those columns with MASKED_<first 6 chars of md5>.
    hashlib.md5(value.encode()).hexdigest()[:6] gives a stable, irreversible token.
    The original value is gone from the output — only its token remains.

 2. safe_plot(df, x_col, y_col, title)
    Before any chart is rendered, check whether x_col or y_col is a PII column.
    If a PII column is passed directly (without prior masking), raise PIIInPlotError.
    This prevents raw email addresses or phone numbers appearing as axis labels
    or in chart metadata.

 Cognitive story:
    Every chart the agent produces is PII-safe. The masking layer runs
    automatically — the analyst sees revenue trends by region, never
    individual email addresses.

EXAMPLE ──────────────────────────────────────────────────────
import hashlib
import re
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt
import pandas as pd

PII_PATTERNS = ["email", "phone", "ssn", "passport", "national_id"]


class PIIInPlotError(Exception):
    pass


def mask_pii_columns(df: pd.DataFrame, pii_patterns: list) -> pd.DataFrame:
    df = df.copy()
    for col in df.columns:
        if any(re.search(p, col, re.IGNORECASE) for p in pii_patterns):
            df[col] = df[col].astype(str).apply(
                lambda v: "MASKED_" + hashlib.md5(v.encode()).hexdigest()[:6]
            )
    return df


def safe_plot(df: pd.DataFrame, x_col: str, y_col: str, title: str) -> None:
    for col in [x_col, y_col]:
        if any(re.search(p, col, re.IGNORECASE) for p in PII_PATTERNS):
            raise PIIInPlotError(
                f"Column '{col}' matches a PII pattern -- mask it before plotting"
            )
    fig, ax = plt.subplots()
    ax.bar(df[x_col].astype(str), df[y_col])
    ax.set_title(title)
    plt.close(fig)
    print(f"[safe_plot] Chart '{title}' rendered -- no PII columns on axes")
