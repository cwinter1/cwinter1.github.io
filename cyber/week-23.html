Concept 1 — BTL1 Exam Structure and Domain Map

BTL1 (Blue Team Labs One) is a practical, hands-on certification. Unlike multiple-choice exams, BTL1 gives you a simulated environment and asks you to answer questions by actually investigating. Think of it like a live code review you can't Google your way out of — you must demonstrate the skill, not just recognize a correct answer.

Six domains, each weighted:

  • Security Fundamentals (10 %): CIA triad, threat modeling, attacker lifecycle
  • Phishing Analysis (20 %): email header forensics, IOC extraction, sandbox analysis
  • Threat Intelligence (10 %): MITRE ATT&CK, CTI feeds, IOC pivoting
  • Digital Forensics (20 %): disk and memory artifacts, timeline reconstruction
  • SIEM (20 %): KQL/SPL queries, alert triage, detection logic
  • Incident Response (20 %): containment, eradication, reporting

Passing score: 70 %. Exam window: 24 hours. No surveillance — open-book, open-lab.

Concept 3 — BTL1 Weak-Spot Identification


Reviewing for a practical exam means identifying which lab skills feel uncertain — not which topics you can describe from memory. The goal is to produce a gap list you can act on: specific lab exercises to repeat in the last week before exam day.


This mirrors the gap analysis you built in W12 for detection coverage: knowing where you are is the prerequisite for knowing where to focus.


Example:


from dataclasses import dataclass, field

@dataclass
class SkillSelfAssessment:
    domain: str
    skill: str
    confidence: int      # 1 = cannot do it; 5 = can do it fast with no notes
    last_practiced: str  # ISO date string YYYY-MM-DD

def gap_list(assessments: list[SkillSelfAssessment], threshold: int = 3) -> list[SkillSelfAssessment]:
    gaps = [a for a in assessments if a.confidence < threshold]
    return sorted(gaps, key=lambda a: a.confidence)

sample = [
    SkillSelfAssessment("siem", "Write KQL time-window aggregation", 4, "2026-05-01"),
    SkillSelfAssessment("digital_forensics", "Run Volatility netscan", 2, "2026-04-20"),
    SkillSelfAssessment("phishing_analysis", "Interpret DMARC policy in headers", 1, "2026-04-15"),
    SkillSelfAssessment("incident_response", "Write containment recommendation", 3, "2026-05-03"),
]

gaps = gap_list(sample)
print("Priority practice list:")
for g in gaps:
    print(f"  [{g.confidence}/5] {g.domain}: {g.skill} (last: {g.last_practiced})")

Concept 2 — SC-200 KQL Pattern Recognition


SC-200 KQL questions follow predictable patterns. The exam does not test obscure KQL syntax — it tests whether you understand aggregation, time windows, joins, and the SecurityEvent / SigninLogs table schemas. Knowing these five patterns covers the majority of KQL questions.


Example:


KQL_EXAM_PATTERNS = [
    {
        "pattern": "Failed login threshold",
        "query": """
SecurityEvent
| where EventID == 4625
| summarize FailedLogins = count() by Account, IpAddress, bin(TimeGenerated, 1h)
| where FailedLogins > 10
""",
        "what_it_detects": "Brute force — more than 10 failed logins per hour per IP",
        "common_trap": "Forgetting bin() — without it, each event is its own row and summarize doesn't aggregate",
    },
    {
        "pattern": "Lateral movement — new process from unusual parent",
        "query": """
DeviceProcessEvents
| where InitiatingProcessFileName in~ ("winword.exe", "excel.exe", "outlook.exe")
| where FileName in~ ("cmd.exe", "powershell.exe", "wscript.exe")
| project Timestamp, DeviceName, InitiatingProcessFileName, FileName, ProcessCommandLine
""",
        "what_it_detects": "Office process spawning a shell — common macro execution pattern",
        "common_trap": "Using == instead of in~ — misses case variants and multiple parent processes",
    },
    {
        "pattern": "Impossible travel — sign-in from two distant locations",
        "query": """
SigninLogs
| where ResultType == 0
| summarize Locations = make_set(Location), SigninCount = count() by UserPrincipalName, bin(TimeGenerated, 1h)
| where array_length(Locations) > 1
""",
        "what_it_detects": "Successful sign-ins from multiple geographic locations within 1 hour",
        "common_trap": "Not filtering ResultType == 0 — failed logins from many locations are normal",
    },
]

for p in KQL_EXAM_PATTERNS:
    print(f"Pattern: {p['pattern']}")
    print(f"Detects: {p['what_it_detects']}")
    print(f"Trap: {p['common_trap']}\n")

Concept 3 — SC-200 Sentinel Analytics Rule Anatomy


SC-200 tests Sentinel analytics rules — the JSON/YAML structure behind the detections you write in the portal. Understanding this anatomy lets you answer questions about rule type, frequency, lookback period, and severity without needing to access a live workspace.


This maps directly to the Sigma rules you wrote in W10 and W13: the concepts are the same; only the serialization format differs.


Example:


from dataclasses import dataclass
from typing import Literal

@dataclass
class SentinelAnalyticsRule:
    display_name: str
    description: str
    severity: Literal["Low", "Medium", "High", "Critical"]
    query: str
    query_frequency: str    # ISO 8601 duration, e.g. "PT5M", "PT1H", "P1D"
    query_period: str       # lookback window
    trigger_operator: Literal["GreaterThan", "Equal", "LessThan", "GreaterThanOrEqual"]
    trigger_threshold: int
    tactics: list[str]      # MITRE ATT&CK tactic names
    techniques: list[str]   # MITRE ATT&CK technique IDs

    def validate(self) -> list[str]:
        errors = []
        if self.trigger_threshold < 0:
            errors.append("trigger_threshold must be >= 0")
        if not self.tactics:
            errors.append("at least one tactic required")
        valid_severities = {"Low", "Medium", "High", "Critical"}
        if self.severity not in valid_severities:
            errors.append(f"severity must be one of {valid_severities}")
        return errors

rule = SentinelAnalyticsRule(
    display_name="Brute Force Against Azure AD",
    description="Detects more than 10 failed sign-ins from a single IP within 1 hour",
    severity="High",
    query="""
SigninLogs
| where ResultType != 0
| summarize FailedAttempts = count() by IPAddress, bin(TimeGenerated, 1h)
| where FailedAttempts > 10
""",
    query_frequency="PT1H",
    query_period="PT1H",
    trigger_operator="GreaterThan",
    trigger_threshold=0,
    tactics=["CredentialAccess"],
    techniques=["T1110"],
)

errors = rule.validate()
print("Validation errors:", errors if errors else "None")
print(f"Rule: {rule.display_name} | Severity: {rule.severity}")
print(f"Runs every {rule.query_frequency}, looks back {rule.query_period}")

Concept 1 — GCIA Domain Map and Exam Format

Concept 2 — TCP/IP Protocol Fields for GCIA


GCIA questions go deep on protocol field values. The exam will show you a hex dump or Wireshark field summary and ask you to identify the anomaly. The most frequently tested: TCP flags, IP TTL values, ICMP type/code combinations, and DNS query types. These are the fields where attackers hide covert channels and evasion techniques.


Example:


TCP_FLAGS = {
    "SYN":     0x02,  # new connection request
    "ACK":     0x10,  # acknowledgment
    "RST":     0x04,  # reset — connection refused or aborted
    "FIN":     0x01,  # graceful close
    "PSH":     0x08,  # push data immediately (no buffer wait)
    "URG":     0x20,  # urgent pointer valid
    "SYN+ACK": 0x12,  # response to SYN during handshake
    "NULL":    0x00,  # no flags — used in stealth scans (GCIA exam favorite)
    "XMAS":    0x29,  # FIN+PSH+URG set — stealth scan, illegal per RFC 793
}

IP_TTL_OS_SIGNATURES = {
    "Windows":     128,
    "Linux":        64,
    "Cisco IOS":   255,
    "Solaris":     255,
}

ICMP_TYPE_CODES = {
    (0, 0): "Echo Reply",
    (3, 0): "Destination Unreachable — Net Unreachable",
    (3, 1): "Destination Unreachable — Host Unreachable",
    (3, 3): "Destination Unreachable — Port Unreachable",
    (8, 0): "Echo Request (ping)",
    (11, 0): "Time Exceeded — TTL expired in transit",
}

def identify_scan_type(flags: int) -> str:
    if flags == TCP_FLAGS["NULL"]:
        return "NULL scan — no flags set, stealth scan"
    if flags == TCP_FLAGS["XMAS"]:
        return "XMAS scan — FIN+PSH+URG, RFC-non-compliant"
    if flags == TCP_FLAGS["FIN"]:
        return "FIN scan — only FIN set, stealth scan"
    if flags == (TCP_FLAGS["SYN"] | TCP_FLAGS["RST"]):
        return "SYN+RST — invalid flag combination, likely crafted packet"
    return "Normal or unrecognized flag combination"

for name, value in [("NULL scan", 0x00), ("XMAS scan", 0x29), ("Normal SYN", 0x02)]:
    print(f"{name} (0x{value:02X}): {identify_scan_type(value)}")

Concept 1 — Competency Map Data Model


A competency map connects curriculum weeks to certification domains. It answers the question: "If I have studied through W12, how much of each cert exam can I cover?" Concept 2 — Exam-Day Simulation Protocol


A "dry run" exam session under realistic conditions is more valuable than 10 hours of passive review. The protocol is simple: set a timer, close all reference material except what is allowed for that specific exam, and answer practice questions without pausing. What you get wrong under time pressure is what actually needs review — not what you hesitate on while casually reading.


Example:


from dataclasses import dataclass, field
from datetime import datetime

@dataclass
class PracticeQuestion:
    question_id: str
    domain: str
    question: str
    correct_answer: str
    your_answer: str = ""
    time_seconds: float = 0.0

    def is_correct(self) -> bool:
        return self.your_answer.strip().lower() == self.correct_answer.strip().lower()

@dataclass
class ExamSession:
    cert: str
    start_time: str
    questions: list[PracticeQuestion] = field(default_factory=list)

    def score(self) -> dict:
        total = len(self.questions)
        if total == 0:
            return {"total": 0, "correct": 0, "pct": 0.0}
        correct = sum(1 for q in self.questions if q.is_correct())
        return {"total": total, "correct": correct, "pct": correct / total * 100}

    def wrong_by_domain(self) -> dict[str, int]:
        result: dict[str, int] = {}
        for q in self.questions:
            if not q.is_correct():
                result[q.domain] = result.get(q.domain, 0) + 1
        return dict(sorted(result.items(), key=lambda x: -x[1]))

    def avg_time_seconds(self) -> float:
        if not self.questions:
            return 0.0
        return sum(q.time_seconds for q in self.questions) / len(self.questions)

    PracticeQuestion("q2", "network_traffic_analysis", "What TTL suggests Linux origin?",    "64",         "128",       30.0),
    PracticeQuestion("q3", "intrusion_detection",      "What Snort keyword limits bytes?",   "depth",      "depth",     60.0),

Concept 3 — Final Readiness Score and Go / No-Go Decision


Before booking an exam seat, you need a go/no-go decision grounded in data, not confidence. Confidence and exam readiness are poorly correlated — experienced professionals often feel less ready than they are (impostor syndrome) while under-prepared candidates sometimes feel ready. A scoring rubric based on practice scores, artifact completion, and gap count gives you a defensible, data-based decision.


Example:


from dataclasses import dataclass

@dataclass
class ReadinessScore:
    cert: str
    practice_score_pct: float      # from practice exam sessions
    artifacts_complete_pct: float  # portfolio artifacts done / required
    domain_gaps: int               # number of GAP domains
    days_since_last_study: int
