Concept 1 — The Detection Coverage Problem

Every signature-based detection is a rule that fires on what analysts already know. A Sigma rule for Mimikatz catches Mimikatz — not the next lateral movement tool that borrows one API and changes two others. This is the coverage cliff: known-bad rules plateau while attacker surface area keeps growing.

ML-based anomaly detection inverts the model. Instead of asking "does this match pattern X?" it asks "does this deviate from what normal looks like?" A process that spawns child processes at 2 a.m. on a server that never runs interactive sessions will score high anomaly even if it has no matching signature.

The tradeoff is precision. Signature rules have near-zero false positives on known patterns; anomaly models alert on statistical rarity, which is not the same as malicious. The SOC workflow changes: signature alerts are verdicts, anomaly alerts are leads.

Data engineering analogy: anomaly detection is like data quality monitoring. You define a schema and thresholds for what "normal" data looks like; anything outside that envelope flags for review. The monitor does not know why the data is wrong — it knows it is unexpected.

Concept 2 — Feature Engineering for Process Behavior


Raw Sysmon events are not ML features. EID 1 fires once per process; EID 7 fires per DLL load; EID 3 fires per network connection. Useful ML features are aggregations: how many children did this process spawn in a 5-minute window? How many distinct destination IPs did it connect to in an hour?


This aggregation step is identical to building a feature store in data engineering. The grain is (process_name, hostname, time_bucket). The metrics are counts, ratios, and rare-event flags.


Feature categories for process behavior:


    

  • Frequency: child spawn rate, DLL load rate, network connection rate
    • 

  • Rarity: process name entropy (DGA-style names), parent-child pair frequency in baseline
    • 

  • Temporal: hour-of-day, day-of-week, time since last execution
    • 

  • Context: interactive session flag, signed binary flag, process path matches known-good paths
    • 



Example:


from dataclasses import dataclass, field
from collections import defaultdict
from typing import Optional
import math

@dataclass
class SysmonEvent:
    event_id: int
    timestamp: str          # "2024-01-15T02:34:11"
    hostname: str
    pid: int
    process_name: str
    parent_pid: Optional[int]
    parent_name: Optional[str]
    target_ip: Optional[str]
    image_path: Optional[str]
    is_signed: Optional[bool]

def aggregate_process_features(
    events: list[SysmonEvent],
    target_process: str,
    target_hostname: str,
) -> dict[str, float]:
    proc_events = [
        e for e in events
        if e.hostname == target_hostname and e.process_name == target_process
    ]
    child_spawn = sum(
        1 for e in events
        if e.parent_name == target_process and e.event_id == 1
    )
    net_conns = sum(
        1 for e in proc_events if e.event_id == 3 and e.target_ip is not None
    )
    dll_loads = sum(1 for e in proc_events if e.event_id == 7)
    unsigned_dlls = sum(
        1 for e in proc_events
        if e.event_id == 7 and e.is_signed is False
    )
    distinct_ips = len({
        e.target_ip for e in proc_events
        if e.event_id == 3 and e.target_ip
    })

    # Name entropy (short, clean names have low entropy)
    name_no_ext = target_process.replace(".exe", "").replace(".dll", "")
    char_freq = defaultdict(int)
    for c in name_no_ext:
        char_freq[c] += 1
    name_len = len(name_no_ext)
    name_entropy = 0.0
    if name_len > 0:
        for count in char_freq.values():
            p = count / name_len
            name_entropy -= p * math.log2(p)

    return {
        "child_spawn_count":      float(child_spawn),
        "network_connection_count": float(net_conns),
        "dll_load_count":         float(dll_loads),
        "unsigned_dll_count":     float(unsigned_dlls),
        "distinct_destination_ips": float(distinct_ips),
        "process_name_entropy":   round(name_entropy, 4),
    }

# Simulate events
EVENTS: list[SysmonEvent] = [
    SysmonEvent(1,  "2024-01-15T02:34:11", "DC01", 4400, "update.exe",  4200, "explorer.exe", None, None, False),
    SysmonEvent(1,  "2024-01-15T02:34:12", "DC01", 4401, "cmd.exe",     4400, "update.exe",   None, None, True),
    SysmonEvent(3,  "2024-01-15T02:34:13", "DC01", 4400, "update.exe",  None, None, "185.220.101.5", None, None),
    SysmonEvent(3,  "2024-01-15T02:34:14", "DC01", 4400, "update.exe",  None, None, "10.0.0.50",     None, None),
    SysmonEvent(7,  "2024-01-15T02:34:15", "DC01", 4400, "update.exe",  None, None, None, "C:\\Temp\\evil.dll", False),
]

Concept 3 — Baseline Collection Strategy


A model trained on attack data learns nothing useful. Isolation Forest needs a clean baseline of "what normal looks like" on the specific host population being monitored. Collecting that baseline is an operational decision with three trade-offs:


Rolling window: use the last 30 days of activity. Adapts to org changes automatically. Risk: if the network is already compromised during baseline collection, malicious behavior becomes "normal."


Static snapshot: collect 2 weeks of data from a known-clean period, freeze the model. Safer against contamination. Requires retraining on a schedule (quarterly) or after major environment changes.


Peer group baseline: train on all hosts of the same role (all domain controllers, all developer workstations). More robust than single-host baseline; catches host-specific anomalies even if common to some hosts but rare across the fleet.


The right choice depends on environment stability and the threat model. For a Detection Engineer, the baseline strategy is as important as the algorithm choice.


Example:


from dataclasses import dataclass, field
from enum import Enum
from typing import Optional
import json

class BaselineStrategy(Enum):
    ROLLING_WINDOW  = "rolling_window"
    STATIC_SNAPSHOT = "static_snapshot"
    PEER_GROUP      = "peer_group"

@dataclass
class BaselineConfig:
    strategy: BaselineStrategy
    lookback_days: int
    host_role: Optional[str]              # for peer_group: "domain_controller", "workstation"
    min_observations: int = 500
    contamination_estimate: float = 0.01  # expected fraction of anomalies in baseline

    def validate(self) -> list[str]:
        issues = []
        if self.lookback_days < 7:
            issues.append("lookback_days < 7 — baseline too short, high variance")
        if self.contamination_estimate > 0.05:
            issues.append("contamination > 5% — model will be noisy")
        if self.strategy == BaselineStrategy.PEER_GROUP and not self.host_role:
            issues.append("peer_group strategy requires host_role")
        return issues

    def to_json(self) -> str:
        return json.dumps({
            "strategy": self.strategy.value,
            "lookback_days": self.lookback_days,
            "host_role": self.host_role,
            "min_observations": self.min_observations,
            "contamination_estimate": self.contamination_estimate,
        }, indent=2)

dc_config = BaselineConfig(
    strategy=BaselineStrategy.PEER_GROUP,
    lookback_days=30,
    host_role="domain_controller",
    min_observations=1000,
    contamination_estimate=0.01,
)

issues = dc_config.validate()
if issues:
    for issue in issues:
        print(f"WARNING: {issue}")
else:
    print("Baseline config OK")
    print(dc_config.to_json())

Concept 1 — How Isolation Forest Works


Isolation Forest is a tree-based anomaly detector. It builds random decision trees by selecting a feature at random and splitting at a random value in the feature's range. Anomalous points — those in sparse regions — are isolated by short paths through the tree. Normal points live in dense regions and require more splits to isolate.


The intuition: normal svchost.exe behavior clusters tightly (same parent, same DLL count, no children). A malicious svchost.exe spawning PowerShell children and making network connections to external IPs occupies a sparse region of feature space — it takes fewer splits to isolate it.


Key hyperparameter: contamination. This is the fraction of the training set that the model treats as anomalous when fitting the decision threshold. Setting it to 0.01 means "I expect 1% of my baseline to be anomalous." If your baseline is clean, set it very low (0.001–0.005).


Data engineering analogy: Isolation Forest is like a partition-based outlier scan. Instead of WHERE clauses, it builds random splits; instead of row counts, it counts the depth needed to reach a row in the tree.


Example:

from typing import Optional

            "max_features": self.max_features,

    """
    Trains an Isolation Forest.
    In real usage:
        from sklearn.ensemble import IsolationForest
        model = IsolationForest(**config.to_sklearn_params())
        model.fit(X_train)
        return model

    for issue in issues:
        print(f"CONFIG WARNING: {issue}")

        "n_samples_trained": len(X_train),
        "n_features": len(X_train[0]) if X_train else 0,
        "contamination": config.contamination,
        "status": "fitted_simulation",

def score_observation(model: dict, observation: list[float]) -> float:
    """
    In real usage:
        score = model.score_samples([observation])[0]  # more negative = more anomalous
        prediction = model.predict([observation])[0]   # -1 = anomaly, 1 = normal
    Simulation: score based on distance from feature mean.
    """
    import statistics
    # Simple z-score distance simulation
    n_features = model["n_features"]
    if n_features == 0:
        return 0.0
    deviations = [abs(v) for v in observation[:n_features]]
    avg_dev = statistics.mean(deviations) if deviations else 0.0
    # Map to [-1, 0]: -1 very anomalous, 0 normal
    simulated_score = max(-1.0, -avg_dev / 20.0)
    return round(simulated_score, 4)

Concept 2 — Scoring and Threshold Calibration


score_samples() returns a continuous score: more negative means more anomalous. The threshold separating "anomaly" from "normal" is not set automatically — the analyst calibrates it.


The calibration workflow:


    

  1. Score the baseline dataset
    2. 

  2. Plot the score distribution — it will have a peak near 0 for normal observations and a tail toward -1
    3. 

  3. Choose a threshold where the false positive rate is operationally acceptable (e.g., ≤ 2% of normal traffic alerts)
    4. 

  4. Validate the threshold on a labeled holdout set (if one exists)
    5. 



The score threshold is not a magic number. It is a business decision: a MSSP handling 10,000 events per hour can tolerate fewer false positives per alert than a small team seeing 200 events per hour.


Example:


from dataclasses import dataclass, field
from typing import Optional

@dataclass
class ScoredObservation:
    observation: "ProcessObservation"
    anomaly_score: float      # more negative = more anomalous
    threshold: float          # decision boundary
    prediction: str = field(init=False)

    def __post_init__(self) -> None:
        self.prediction = "ANOMALY" if self.anomaly_score < self.threshold else "NORMAL"

    def alert_priority(self) -> str:
        if self.anomaly_score < self.threshold - 0.2:
            return "HIGH"
        if self.anomaly_score < self.threshold:
            return "MEDIUM"
        return "NONE"

def calibrate_threshold(
    baseline_scores: list[float],
    target_fpr: float = 0.02,
) -> float:
    """
    Returns threshold such that target_fpr fraction of baseline scores fall below it.
    Equivalent to the (target_fpr * 100)th percentile of baseline scores.
    """
    sorted_scores = sorted(baseline_scores)
    cutoff_index = max(0, int(len(sorted_scores) * target_fpr) - 1)
    return sorted_scores[cutoff_index]

def evaluate_threshold(
    scores: list[float],
    labels: list[int],   # 1 = anomaly, 0 = normal
    threshold: float,
) -> dict[str, float]:
    predictions = [1 if s < threshold else 0 for s in scores]
    tp = sum(1 for p, l in zip(predictions, labels) if p == 1 and l == 1)
    fp = sum(1 for p, l in zip(predictions, labels) if p == 1 and l == 0)
    tn = sum(1 for p, l in zip(predictions, labels) if p == 0 and l == 0)
    fn = sum(1 for p, l in zip(predictions, labels) if p == 0 and l == 1)
    precision = tp / (tp + fp) if (tp + fp) > 0 else 0.0
    recall    = tp / (tp + fn) if (tp + fn) > 0 else 0.0
    fpr       = fp / (fp + tn) if (fp + tn) > 0 else 0.0
    return {"precision": precision, "recall": recall, "fpr": fpr, "tp": tp, "fp": fp, "fn": fn}

# Simulate baseline scores (normal behavior, clustered near 0)
import random
random.seed(42)
baseline_scores = [random.gauss(-0.05, 0.08) for _ in range(200)]

threshold = calibrate_threshold(baseline_scores, target_fpr=0.02)
print(f"Calibrated threshold at 2% FPR: {threshold:.4f}")

# Simulate mixed test set: 180 normal + 20 attack
test_scores  = [random.gauss(-0.05, 0.08) for _ in range(180)]
test_scores += [random.gauss(-0.55, 0.15) for _ in range(20)]
test_labels  = [0] * 180 + [1] * 20

metrics = evaluate_threshold(test_scores, test_labels, threshold)
print(f"Precision: {metrics['precision']:.2f}  Recall: {metrics['recall']:.2f}  FPR: {metrics['fpr']:.3f}")

Concept 3 — Feature Scaling and Preprocessing


Isolation Forest is not distance-based, so it is less sensitive to feature scale than K-Nearest Neighbors or DBSCAN. However, features with vastly different ranges still affect which features dominate the random splits. Normalizing features (StandardScaler or MinMaxScaler) ensures the model gives each feature equal chance of being selected as a split dimension.


Categorical features — process name, parent name — need encoding. Options:


    

  • Binary rare flag: is this process name in the top-100 most common names? (1/0)
    • 

  • Frequency encoding: replace process name with its observed frequency in the baseline
    • 

  • Hashing: hash the string to an integer (fast, loses interpretability)
    • 



For process name entropy, no scaling needed since it already falls in [0, ~4].


Example:


from dataclasses import dataclass
import statistics

@dataclass
class FeatureScaler:
    feature_names: list[str]
    means: list[float] = None
    stds: list[float] = None
    fitted: bool = False

    def fit(self, X: list[list[float]]) -> "FeatureScaler":
        if not X:
            raise ValueError("Cannot fit on empty dataset")
        n_features = len(X[0])
        self.means = []
        self.stds = []
        for i in range(n_features):
            col = [row[i] for row in X]
            self.means.append(statistics.mean(col))
            std = statistics.stdev(col) if len(col) > 1 else 1.0
            self.stds.append(std if std > 0 else 1.0)
        self.fitted = True
        return self

    def transform(self, X: list[list[float]]) -> list[list[float]]:
        if not self.fitted:
            raise RuntimeError("Scaler must be fitted before transform")
        return [
            [(val - self.means[i]) / self.stds[i] for i, val in enumerate(row)]
            for row in X
        ]

    def fit_transform(self, X: list[list[float]]) -> list[list[float]]:
        return self.fit(X).transform(X)

    def transform_one(self, row: list[float]) -> list[float]:
        if not self.fitted:
            raise RuntimeError("Scaler must be fitted before transform")
        return [(val - self.means[i]) / self.stds[i] for i, val in enumerate(row)]

X_raw = [
    [9.0, 0.0, 2.0, 14.0, 0.0, 0.0],
    [10.0, 1.0, 3.0, 16.0, 0.0, 0.0],
    [11.0, 0.0, 0.0, 22.0, 0.0, 0.0],
    [9.5, 0.0, 1.0, 15.0, 0.0, 0.0],
    [10.5, 1.0, 2.0, 18.0, 0.0, 0.0],
]

Concept 1 — Ingesting Sysmon Events for ML


Sysmon logs arrive as Windows Event Log XML or as EVTX. For ML, you need tabular format: one row per process execution window, one column per feature. The pipeline is: parse events → group by (hostname, process_name, time_bucket) → aggregate features → scale → score.


This is the same aggregation-then-score pattern used in fraud detection and network beaconing detection (W14). The key difference: process behavior features are richer and require cross-event-ID joins (EID 1 + EID 3 + EID 7 all contribute to the same process row).


Example:


from dataclasses import dataclass, field
from typing import Optional
from collections import defaultdict
import json

@dataclass
class SysmonRecord:
    event_id: int
    timestamp: str
    hostname: str
    pid: int
    process_name: str
    ppid: Optional[int]
    parent_name: Optional[str]
    image_path: Optional[str]
    command_line: Optional[str]
    target_ip: Optional[str]
    target_port: Optional[int]
    loaded_image: Optional[str]
    is_signed: Optional[bool]
    user: Optional[str]

@dataclass
class ProcessWindow:
    """One row in the ML feature matrix: one process across all its events."""
    hostname: str
    pid: int
    process_name: str
    parent_name: str
    user: str
    first_seen: str
    child_pids: list[int] = field(default_factory=list)
    network_conns: list[str] = field(default_factory=list)
    loaded_dlls: list[str] = field(default_factory=list)
    unsigned_dlls: int = 0
    command_line: str = ""

    def add_event(self, record: SysmonRecord) -> None:
        if record.event_id == 1 and record.ppid == self.pid:
            self.child_pids.append(record.pid)
        elif record.event_id == 3 and record.target_ip:
            self.network_conns.append(record.target_ip)
        elif record.event_id == 7 and record.loaded_image:
            self.loaded_dlls.append(record.loaded_image)
            if record.is_signed is False:
                self.unsigned_dlls += 1

    def to_feature_vector(self) -> list[float]:
        try:
            hour = int(self.first_seen[11:13])
        except (ValueError, IndexError):
            hour = 12.0
        return [
            float(hour),
            float(len(self.child_pids)),
            float(len(set(self.network_conns))),
            float(len(self.loaded_dlls)),
            float(self.unsigned_dlls),
            float(0),  # session_id placeholder
        ]

def build_process_windows(records: list[SysmonRecord]) -> dict[tuple, ProcessWindow]:
    windows: dict[tuple, ProcessWindow] = {}
    for r in records:
        if r.event_id == 1:
            key = (r.hostname, r.pid)
            if key not in windows:
                windows[key] = ProcessWindow(
                    hostname=r.hostname,
                    pid=r.pid,
                    process_name=r.process_name,
                    parent_name=r.parent_name or "",
                    user=r.user or "UNKNOWN",
                    first_seen=r.timestamp,
                    command_line=r.command_line or "",
                )
    for r in records:
        for key, window in windows.items():
            if key[0] == r.hostname:
                window.add_event(r)
    return windows

Concept 2 — Training and Persisting the Model


A trained Isolation Forest must be saved so the same model is used across shifts and restarts. In production, models are versioned artifacts — like Parquet files or dbt models, they have a creation timestamp, a training dataset hash, and a retirement date.


The minimal persistence format: serialize the model with joblib (for sklearn) or pickle (for custom implementations). Alongside the model binary, save a metadata JSON: training date, n_samples, contamination, threshold, feature names, and scaler parameters. The metadata lets a new analyst reconstruct what the model represents without running the training pipeline.


Example:


from dataclasses import dataclass, field
from typing import Optional
import json
import hashlib

@dataclass
class ModelMetadata:
    model_id: str
    created_at: str
    training_host_role: str
    n_samples: int
    n_features: int
    feature_names: list[str]
    contamination: float
    threshold: float
    scaler_means: list[float]
    scaler_stds: list[float]
    baseline_strategy: str
    notes: str = ""

    def to_json(self) -> str:
        return json.dumps(self.__dict__, indent=2)

    @classmethod
    def from_json(cls, data: str) -> "ModelMetadata":
        return cls(**json.loads(data))

    def fingerprint(self) -> str:
        """SHA-256 of metadata (excluding notes) for change detection."""
        stable = {k: v for k, v in self.__dict__.items() if k != "notes"}
        raw = json.dumps(stable, sort_keys=True).encode()
        return hashlib.sha256(raw).hexdigest()[:16]

def save_model_metadata(meta: ModelMetadata, path: str) -> None:
    """
    Real usage:
        import joblib
        joblib.dump({"model": model, "scaler": scaler, "meta": meta}, path)
    Simulation: write metadata JSON to <path>.meta.json
    """
    meta_path = path + ".meta.json"
    with open(meta_path, "w") as f:
        f.write(meta.to_json())
    print(f"Metadata saved to {meta_path}")

def load_model_metadata(path: str) -> ModelMetadata:
    meta_path = path + ".meta.json"
    with open(meta_path) as f:
        return ModelMetadata.from_json(f.read())

Concept 1 — Evaluating an Anomaly Model Without Ground Truth


Anomaly detection in security is semi-supervised: the training set is assumed normal, but there is no clean labeled test set of attacks. Evaluation options:


Red team labeled data: if you ran a red team exercise, use those events as the positive class. Precision and recall against red team events are the most meaningful metrics.


Synthetic attacks: inject known-malicious feature vectors into the test set (e.g., a mimikatz.exe feature profile). Useful for regression testing after model updates.


Operational metrics: false-positive rate measured by analyst verdict (analyst closes alert as FP → record that score). Over time, build a FP label set for threshold re-calibration.


Cluster analysis: cluster the anomaly-scored observations; inspect the anomalous cluster manually. If it contains known-bad processes, the model is working. If it contains legitimate business applications running at odd hours, the baseline needs adjustment.


Example:


from dataclasses import dataclass, field
from typing import Optional
import statistics

@dataclass
class EvaluationResult:
    model_id: str
    eval_date: str
    n_total: int
    n_anomalies_flagged: int
    n_true_positives: int    # confirmed malicious
    n_false_positives: int   # analyst closed as FP
    n_false_negatives: int   # known-bad that model missed
    threshold_used: float
    notes: str = ""

    def precision(self) -> float:
        denom = self.n_true_positives + self.n_false_positives
        return self.n_true_positives / denom if denom > 0 else 0.0

    def recall(self) -> float:
        denom = self.n_true_positives + self.n_false_negatives
        return self.n_true_positives / denom if denom > 0 else 0.0

    def false_positive_rate(self) -> float:
        n_normal = self.n_total - self.n_true_positives - self.n_false_negatives
        denom = n_normal
        return self.n_false_positives / denom if denom > 0 else 0.0

    def summary(self) -> str:
        return (
            f"Model {self.model_id} | "
            f"Precision={self.precision():.2f} Recall={self.recall():.2f} "
            f"FPR={self.false_positive_rate():.3f} | "
            f"TP={self.n_true_positives} FP={self.n_false_positives} FN={self.n_false_negatives}"
        )

def compare_evaluations(results: list[EvaluationResult]) -> None:
    for r in sorted(results, key=lambda x: x.eval_date):
        print(r.summary())

Concept 2 — Feature Drift Detection


An anomaly model trained in January will degrade by March if software deployments changed process behavior on the fleet. Windows Update might introduce a new svchost.exe pattern that the January baseline never saw; the model flags it as anomalous even though it is legitimate.


Feature drift detection: periodically compute the distribution of each feature in the current window and compare it to the training baseline. If the KL divergence or the mean shift exceeds a threshold, trigger a retrain.


Practical approach for detection teams: track rolling 7-day feature means. If any feature mean drifts more than 2 standard deviations from the training mean, raise a "baseline staleness" alert — not a security alert, but an operational one for the detection engineer.


Example:


from dataclasses import dataclass, field
from typing import Optional
import statistics
import math

@dataclass
class FeatureDriftReport:
    feature_name: str
    training_mean: float
    training_std: float
    current_mean: float
    current_std: float
    z_score_of_mean: float = field(init=False)
    drift_detected: bool = field(init=False)
    drift_threshold_z: float = 2.0

    def __post_init__(self) -> None:
        if self.training_std > 0:
            self.z_score_of_mean = abs(self.current_mean - self.training_mean) / self.training_std
        else:
            self.z_score_of_mean = 0.0
        self.drift_detected = self.z_score_of_mean > self.drift_threshold_z

def detect_feature_drift(
    training_stats: dict[str, dict],
    current_observations: list[list[float]],
    feature_names: list[str],
) -> list[FeatureDriftReport]:
    reports = []
    for i, name in enumerate(feature_names):
        col = [row[i] for row in current_observations]
        current_mean = statistics.mean(col) if col else 0.0
        current_std  = statistics.stdev(col) if len(col) > 1 else 0.0
        stats = training_stats.get(name, {"mean": 0.0, "stdev": 1.0})
        reports.append(FeatureDriftReport(
            feature_name=name,
            training_mean=stats["mean"],
            training_std=stats["stdev"],
            current_mean=current_mean,
            current_std=current_std,
        ))
    return reports

Concept 3 — Model Retraining Governance


Retraining a production anomaly model is a risk event. If the new baseline accidentally incorporates attacker behavior, the model becomes blind to the active intrusion. Retraining governance requires:


    

  1. Human approval gate: a detection engineer reviews the drift report and approves retraining
    2. 

  2. Contamination scan: before training, run existing YARA and Sigma rules against the proposed baseline dataset — reject it if more than the contamination threshold of events match
    3. 

  3. Shadow deployment: run the new model in parallel with the old one for 24 hours, compare alert rates and overlap
    4. 

  4. Rollback path: keep the previous model version active; rollback procedure is documented
    5. 



This mirrors blue/green deployment from software engineering. The old model is "blue" (stable); the new model is "green" (candidate). You cut over only after validation.


Example:


from dataclasses import dataclass, field
from enum import Enum
from typing import Optional
import json

class RetrainingStatus(Enum):
    PROPOSED    = "proposed"
    CONTAMINATION_CHECK = "contamination_check"
    APPROVED    = "approved"
    SHADOW_RUNNING = "shadow_running"
    PROMOTED    = "promoted"
    REJECTED    = "rejected"
    ROLLED_BACK = "rolled_back"

@dataclass
class RetrainingRequest:
    request_id: str
    model_id: str
    new_version: str
    triggered_by: str         # "drift_alert" or "schedule" or "manual"
    drift_features: list[str]
    proposed_baseline_size: int
    contamination_fraction: float   # from YARA/Sigma scan of proposed baseline
    status: RetrainingStatus = RetrainingStatus.PROPOSED
    approver: Optional[str] = None
    rejection_reason: Optional[str] = None
    shadow_alert_delta_pct: Optional[float] = None  # new_alerts / old_alerts - 1

    MAX_CONTAMINATION = 0.02

    def approve_retraining(self, approver: str) -> bool:
        if self.contamination_fraction > self.MAX_CONTAMINATION:
            self.status = RetrainingStatus.REJECTED
            self.rejection_reason = (
                f"Contamination {self.contamination_fraction:.1%} exceeds "
                f"max {self.MAX_CONTAMINATION:.1%}"
            )
            return False
        self.approver = approver
        self.status = RetrainingStatus.APPROVED
        return True

    def start_shadow(self) -> None:
        if self.status != RetrainingStatus.APPROVED:
            raise RuntimeError("Cannot start shadow: request not approved")
        self.status = RetrainingStatus.SHADOW_RUNNING

    def promote(self, shadow_delta: float) -> None:
        self.shadow_alert_delta_pct = shadow_delta
        if abs(shadow_delta) > 0.50:
            self.status = RetrainingStatus.REJECTED
            self.rejection_reason = f"Shadow alert delta {shadow_delta:.0%} exceeds ±50%"
            return
        self.status = RetrainingStatus.PROMOTED

    def to_json(self) -> str:
        d = self.__dict__.copy()
        d["status"] = self.status.value
        return json.dumps(d, indent=2)

    model_id="iforest_dc_v2",
    new_version="v3",
    triggered_by="drift_alert",

)

Concept 1 — Wrapping ML Detections as Sigma-Compatible Alerts


Sigma rules are the standard format for detection logic in the SOC. An ML anomaly score is not a Sigma rule — it is a continuous score from a model. To integrate into a SIEM workflow, the ML output needs to be materialized as a structured event that a Sigma rule can match.


Pattern: the anomaly pipeline writes a synthetic event to a log stream (e.g., a custom table ml_anomalies) with fields: alert_id, anomaly_score, priority, process_name, hostname. A Sigma rule then matches on priority: HIGH in that table. This way, the ML model is treated like any other log source — it produces structured events, and analysts write rules against those events.


Example:


from dataclasses import dataclass
import json

@dataclass
class MLAnomalyEvent:
    """Synthetic event written to SIEM for downstream Sigma matching."""
    event_source: str = "ml_anomaly_detector"

Concept 2 — Connecting ML Output to the Detection Pipeline


The anomaly detector fits into the detection pipeline as a processing stage, not a replacement for Sigma rules. The architecture:


Sysmon events
    → Aggregation layer (build ProcessWindows)
    → Feature extraction
    → Scale
    → Isolation Forest score
    → Threshold filter
    → MLAnomalyEvent written to synthetic log stream
    → SIEM ingests synthetic log stream
    → Sigma rule on ml_anomaly_detector fires
    → Alert in queue
    → Analyst triage

For Python-based pipelines (offline or near-real-time), the full pipeline runs as a scheduled job. The output is a JSON file of MLAnomalyEvent records that the SIEM imports on the next ingest cycle.


Example:


from dataclasses import dataclass, field
from typing import Optional
import json

@dataclass
class PipelineRun:
    run_id: str
    started_at: str
    model_id: str
    n_events_ingested: int = 0
    n_windows_built: int = 0
    n_scored: int = 0
    n_anomalies: int = 0
    n_high_priority: int = 0
    output_path: str = ""
    errors: list[str] = field(default_factory=list)
    completed_at: Optional[str] = None

    def record_error(self, msg: str) -> None:
        self.errors.append(msg)

    def to_json(self) -> str:
        return json.dumps(self.__dict__, indent=2)

def run_anomaly_pipeline(
    events: list,
    model_meta: "ModelMetadata",
    scaler: "FeatureScaler",
    threshold: float,
    output_path: str,
    run_id: str,
) -> PipelineRun:
    """
    Full pipeline: events → windows → features → scale → score → alerts.
    Uses simulated scoring since sklearn not required.
    """
    run = PipelineRun(
        run_id=run_id,
        started_at="2024-01-15T03:00:00Z",
        model_id=model_meta.model_id if model_meta else "unknown",
        output_path=output_path,
    )
    run.n_events_ingested = len(events)

    try:
        windows = build_process_windows(events) if "build_process_windows" in dir() else {}
        run.n_windows_built = len(windows)

        alerts: list[MLAnomalyEvent] = []
        for key, window in windows.items():
            raw_fv = window.to_feature_vector()
            if scaler and scaler.fitted:
                scaled_fv = scaler.transform_one(raw_fv)
            else:
                scaled_fv = raw_fv

            # Simulate score
            import statistics
            z_scores = [abs(v) for v in scaled_fv]
            simulated_score = -statistics.mean(z_scores) / 5.0 if z_scores else 0.0
            run.n_scored += 1

            if simulated_score < threshold:
                run.n_anomalies += 1
                priority = "HIGH" if simulated_score < threshold - 0.2 else "MEDIUM"
                if priority == "HIGH":
                    run.n_high_priority += 1

                feat_names = model_meta.feature_names if model_meta else [str(i) for i in range(len(raw_fv))]
                top = sorted(zip(feat_names, raw_fv, scaled_fv),
                             key=lambda x: abs(x[2]), reverse=True)

                alert = MLAnomalyEvent(
                    model_id=model_meta.model_id if model_meta else "unknown",
                    alert_id=f"{run_id}-{key[1]}",
                    timestamp=window.first_seen,
                    hostname=window.hostname,
                    pid=window.pid,
                    process_name=window.process_name,
                    parent_name=window.parent_name,
                    anomaly_score=simulated_score,
                    priority=priority,
                    top_feature_1=top[0][0] if len(top) > 0 else "",
                    top_feature_1_z=round(top[0][2], 2) if len(top) > 0 else 0.0,
                    top_feature_2=top[1][0] if len(top) > 1 else "",
                    top_feature_2_z=round(top[1][2], 2) if len(top) > 1 else 0.0,
                )
                alerts.append(alert)

        run.completed_at = "2024-01-15T03:00:05Z"

        with open(output_path, "w") as f:
            json.dump([json.loads(a.to_siem_json()) for a in alerts], f, indent=2)
        print(f"Pipeline complete: {run.n_anomalies} anomalies written to {output_path}")

    except Exception as e:
        run.record_error(str(e))

    return run

Concept 3 — ML Coverage Gaps and Limitations


ML anomaly detection is a complement to signature-based detection, not a replacement. The coverage gap map:






Attack pattern
Best detector






Known malware hash
File hash rule (Sigma/YARA)




Known C2 domain
DNS/proxy rule (Sigma/TI feed)




Novel process injection
Anomaly detector (behavioral deviation)




Novel living-off-the-land
Anomaly detector (rare parent-child pairs)




Slow-burn persistence
Anomaly detector (if baseline is clean)




Fileless attacks
Memory scanning (YARA on process memory) + anomaly




Credential dumping
Sigma on LSASS access events (EID 4656 + EID 10)






The detection engineer's job is to know which quadrant each detection lives in and ensure coverage across all attack patterns, not just the ones that are easy to write rules for.


Example:


from dataclasses import dataclass, field
from enum import Enum
from typing import Optional

class DetectorType(Enum):
    SIGNATURE  = "signature"    # Sigma, YARA, IOC match
    ANOMALY    = "anomaly"      # ML model, statistical baseline
    HYBRID     = "hybrid"       # Sigma on ML output + direct rule

@dataclass
class CoverageEntry:
    technique_id: str
    technique_name: str
    primary_detector: DetectorType
    fallback_detector: Optional[DetectorType]
    ml_adds_value: bool
    ml_limitation: str
    detection_asset: str        # rule name, model name, or "GAP"

def build_coverage_map() -> list[CoverageEntry]:
    return [
        CoverageEntry("T1055.012", "Process Hollowing",
                      DetectorType.ANOMALY, DetectorType.SIGNATURE, True,
                      "Slow injection evasion keeps feature values in range",
                      "iforest_dc_v2 + YARA T1055_hollow_process_injector"),
        CoverageEntry("T1003.001", "LSASS Memory Dump",
                      DetectorType.SIGNATURE, None, False,
                      "LSASS access is rare; anomaly model not needed",
                      "Sigma: lsass_access_eid4656"),
        CoverageEntry("T1059.001", "PowerShell Execution",
                      DetectorType.HYBRID, DetectorType.SIGNATURE, True,
